# План и журнал реализации

## Этапы

1. **Домен и база.** Контрактные тесты, ограничения SQL, нормализация UTC, транзакции и вычисление пикового пересечения.
2. **Сервис проката.** Атомарные комплекты, сохранённые цены, идемпотентность, TTL, переходы, переносы, остатки и аудит. Конкурентные клиенты на двух базах.
3. **HTTP-граница.** Валидация, роли ключей, ограниченные выборки, ошибки и отдельный демонстрационный режим.
4. **Рабочее место.** Доска, поиск, фильтры, создание, инспектор, перенос, действия, временная шкала, физический остаток, каталог и журнал.
5. **Воспроизводимость.** Демо-наполнение, CLI, PostgreSQL/Docker, CI, русская документация и проверка браузером.

## На что смотреть при дальнейшем ревью

Точная граница TTL; порядок блокировок нескольких позиций; ключ одинакового пользователя на разных пулах; суммирование по сегментам; физически выданные просроченные единицы; границы суммы; момент проверки времени после ожидания; сохранение ключа браузером при сетевом повторе.

Новый крупный функциональный этап требует отдельного изменения доменного контракта. Буферы подготовки, ремонт и частичный возврат не выдаются за реализованные возможности.

- Дополнительное ревью: устойчивый ID отделён от имени пользователя; ротация/переименование не меняют область идемпотентности. Авторство хранит ID и снимок имени. Три теста проверяют этот контракт.
- На мобильном экране добавлена доступная кнопка смены ключа, устранено пересечение текста метрик со значками. Справка CLI и ошибки параметров переведены локальным подклассом argparse; три сценария проверяются исполнением.
- Docker отсутствует в локальном окружении: конфигурация подготовлена, контейнерная сборка не заявляется проверенной.

- Установочный wheel собран стандартным изолированным процессом pip. Первая попытка без изоляции выявила отсутствие setuptools в общей среде; общая среда не изменялась. Временные сборочные зависимости размещены внутри игнорируемого artifacts/.


## Второй этап: точные альтернативы

- Контракт согласован отдельно и проверен независимым рецензентом до реализации. Поиск только для новых броней; ограничения и алгоритм — в `docs/alternatives.md`.
- Сначала воспроизведены 19 падающих доменных сценариев, затем реализован поиск через единый SELECT и точное объединение интервалов. Дополнительные тесты поймали выход за диапазон UTC и отсутствие HTTP-маршрута до их исправления.
- Полный набор: **68/68 SQLite, 68/68 PostgreSQL 17.11**, три Node-теста точного применения даты. Ruff, форматирование и синтаксис JavaScript проходят.
- Независимый алгоритм сравнения: 414 SQLite и 134 PostgreSQL набора; цена, количества, полные диапазоны, отсутствие записи, согласованность снимка и конкурентное резервирование после рекомендации — без найденных расхождений.
- Реальный браузер: конфликт → два свободных участка → выбор → резерв с сохранением шести знаков дробной секунды в API → отмена учебной брони. Физическая просрочка показана отдельным предупреждением.
- Исходники HTML/CSS/JS отформатированы читаемо; форматировщик не стал зависимостью приложения.
- Чистый архив базового коммита установлен в новом окружении по README: 44 теста и проверка стиля прошли, установленная CLI-команда запустила демо с 8 позициями и 7 бронями. Проверочный сервер остановлен; копия сохранена.
- Добавлен отдельный CI-шаг Docker Compose. Его HTTP-сценарий прошёл локально; проверка контейнера ожидает удалённого запуска нового коммита. Старый успешный CI не выдаётся за проверку нового кода.


## Третий этап: надёжность существующего ядра

- Второй этап сохранён в `5171082`; [CI 41363574229](https://github.com/GrantCanyon/orderflow/actions/runs/41363574229) прошёл обе базы и реальный Docker Compose.
- Добавлены ограниченное ожидание блокировок и безопасная классификация ошибок без SQL/параметров/ключей. Тесты сначала воспроизвели отсутствие контракта; затем проверены реальные блокировки PostgreSQL/SQLite и повтор после их снятия.
- После каждого из четырёх INSERT вызывается реальная ошибка SQL в тестовом обработчике; полный откат и повтор ключа проверены независимым соединением. Тестовый сетевой прокси получает upstream201 и обрывает downstream: повтор возвращает ту же бронь без дубля аудита.
- Создан воспроизводимый HTTP-стенд: общий/отдельные пулы, одинаковый seed, сырые задержки, ближайшие ранги и независимая сверка состояния. Прогрев не включён в задержки. Системный прокси отключён для loopback; отдельный тест подтвердил это с заведомо недоступным HTTP_PROXY.
- Выполнено по шесть испытаний SQLite и PostgreSQL: 200 исходных запросов, 8 клиентов, 3 повтора каждого сценария; во всех 12 случаях 96 уникальных фиксаций, 104 конфликта и 40 повторов, без нарушения инвариантов. Численные результаты и ограничения представлены в `docs/reliability.md`.
- Независимый рецензент подтвердил откаты/сетевое восстановление/реальные таймауты, пересчитал сырые задержки и наблюдал записи исключительно в собственные временные схемы; `public` не менялся, схемы удалены.
- Дополнительное ревью нашло NUL/Unicode-паритет и отсутствие верхнего предела числовых ID. Обе ошибки воспроизведены до исправления. NUL/суррогаты запрещены без запрета кириллицы/newline; положительный signed32-предел одинаков на API и сервисе, обычная пагинация и количества не менялись.
- Итоговый набор этого этапа: 92 теста Python на двух конфигурациях базы и 3 теста дат Node. Локальные доказательства и независимые проверки не выдаются за ещё не выполненный CI нового коммита.
