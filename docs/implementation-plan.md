# План и журнал реализации

## Этапы

1. **Домен и база.** Контрактные тесты, ограничения SQL, нормализация UTC, транзакции и вычисление пикового пересечения.
2. **Сервис проката.** Атомарные комплекты, сохранённые цены, идемпотентность, TTL, переходы, переносы, остатки и аудит. Конкурентные клиенты на двух базах.
3. **HTTP-граница.** Валидация, роли ключей, ограниченные выборки, ошибки и отдельный демонстрационный режим.
4. **Рабочее место.** Доска, поиск, фильтры, создание, инспектор, перенос, действия, временная шкала, физический остаток, каталог и журнал.
5. **Воспроизводимость.** Демо-наполнение, CLI, PostgreSQL/Docker, CI, русская документация и проверка браузером.

## Журнал 02.11.2026

- Исходная точка: согласованный контракт и 18 тестов, исходного сервиса ещё нет. Набор воспроизведён красным из-за отсутствующей реализации.
- Реализованы домен и транзакции: 18 исходных тестов прошли на SQLite.
- Добавлены гонки независимых соединений: общий ресурс, одинаковый ключ, разные пулы, обратный порядок позиций, уменьшение парка. Отдельные падающие тесты воспроизвели отсутствие физической проверки выдачи и уменьшения остатка; после исправления 26 тестов прошли на обеих базах.
- Fixture PostgreSQL создаёт случайную собственную схему; очистка чужих таблиц исключена. Для SQLite используются временные файлы.
- Добавлены HTTP-контракт, роли, demo isolation, строгая валидация, раздельный физический/плановый остаток и повторяемое наполнение: 34 теста.
- Независимое ревью обнаружило две ошибки: проверку времени переноса до ожидания блокировки и переполнение PostgreSQL `INTEGER` при допустимой сумме. Обе воспроизведены новыми тестами до изменения кода. Исправлены проверкой после блокировки и `BIGINT` с безопасным пределом JSON. Небезопасный итог отклоняется до записи и при переносе.
- Последняя полная локальная проверка: **44/44 SQLite, 44/44 PostgreSQL 17.11**, Ruff без ошибок, форматирование без изменений, JavaScript проходит проверку синтаксиса.
- Независимая проверка реального браузера прошла сценарий: конфликт с конкретной бронью → успешный резерв → подтверждение → недоступная ранняя выдача → перенос с перерасчётом → отмена → четыре события аудита. Ошибок/предупреждений в консоли этого сценария не было.
- Настроен CI для двух баз. Удалённый запуск CI ещё не заявляется.

В тестовом окружении зависимость Starlette выдаёт одно предупреждение о будущем клиенте `httpx2`; оно не скрыто. Проверка контейнерной сборки зависит от наличия Docker и фиксируется отдельно.

## На что смотреть при дальнейшем ревью

Точная граница TTL; порядок блокировок нескольких позиций; ключ одинакового пользователя на разных пулах; суммирование по сегментам; физически выданные просроченные единицы; границы суммы; момент проверки времени после ожидания; сохранение ключа браузером при сетевом повторе.

Новый крупный функциональный этап требует отдельного изменения доменного контракта. Буферы подготовки, ремонт и частичный возврат не выдаются за реализованные возможности.

- Дополнительное ревью: устойчивый ID отделён от имени пользователя; ротация/переименование не меняют область идемпотентности. Авторство хранит ID и снимок имени. Три теста проверяют этот контракт.
- На мобильном экране добавлена доступная кнопка смены ключа, устранено пересечение текста метрик со значками. Справка CLI и ошибки параметров переведены локальным подклассом argparse; три сценария проверяются исполнением.
- Docker отсутствует в локальном окружении: конфигурация подготовлена, контейнерная сборка не заявляется проверенной.

- Установочный wheel собран стандартным изолированным процессом pip. Первая попытка без изоляции выявила отсутствие setuptools в общей среде; общая среда не изменялась. Временные сборочные зависимости размещены внутри игнорируемого artifacts/.
