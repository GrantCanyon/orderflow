# HTTP API

Базовый адрес при локальном запуске: `http://127.0.0.1:8000`. Полный машинный контракт доступен в `/openapi.json`. Страницы `/docs` и `/redoc` намеренно отключены: стандартные страницы используют внешние CDN, а приложение ограничивает источники своей политикой CSP.

## Авторизация

Каждый запрос к данным содержит `X-API-Key`. Ключ сопоставлен объекту `{id, name, role}` из `ORDERFLOW_API_KEYS`. `id` — устойчивый идентификатор пользователя, `name` — отображаемое имя. Два ключа одного `id` допустимы при ротации. Одинаковые имена разных пользователей не объединяют их данные идемпотентности.

| Роль | Полномочия |
|---|---|
| `viewer` | Чтение каталога, броней, доступности и аудита |
| `operator` | Чтение, создание, перенос и действия с бронями |
| `admin` | Всё выше, изменение каталога и завершение истёкших резервов |

Это общая рабочая область одной организации. Наблюдатель видит все бронирования; владение отдельной бронью не ограничивает чтение или работу оператора.

## Маршруты

| Метод и путь | Назначение |
|---|---|
| `GET /health` | Доступность приложения и базы, без ключа |
| `GET /api/config` | Публичные параметры деморежима, валюта, TTL |
| `GET /api/me` | Текущие `id`, `name`, `role` |
| `GET /api/products` | Каталог |
| `POST /api/products` | Добавить позицию; администратор |
| `PATCH /api/products/{id}` | Изменить имя, категорию, остаток, ставку; администратор |
| `GET /api/availability?start=…&end=…` | Доступность и временные сегменты |
| `POST /api/alternatives` | Найти точные свободные периоды для нового комплекта, без записи |
| `GET /api/bookings` | Список с `status`, `search`, `limit` 1–200 и `offset` |
| `GET /api/bookings/{id}` | Бронь, позиции и эффективный статус |
| `POST /api/bookings` | Создать резерв; обязателен `Idempotency-Key` |
| `PATCH /api/bookings/{id}/schedule` | Перенести период |
| `POST /api/bookings/{id}/confirm` | Подтвердить резерв |
| `POST /api/bookings/{id}/cancel` | Отменить до выдачи |
| `POST /api/bookings/{id}/check_out` | Выдать с физической проверкой |
| `POST /api/bookings/{id}/return` | Принять полный возврат |
| `GET /api/audit` | Аудит; `booking_id`, `limit` 1–200, `before_id` |
| `POST /api/admin/expire` | Материализовать истёкшие резервы; администратор |

В фильтре броней допустимы `hold`, `confirmed`, `checked_out`, `returned`, `cancelled`, `expired`, `overdue`. `overdue` — вычисляемый признак невозвращённой выдачи после окончания периода. Список упорядочен по времени создания от новых к старым и затем по ID; аудит — по убывающему номеру.

## Создание бронирования

Пример тела; даты нужно заменить будущими:

```json
{
  "label": "Учебный концерт",
  "start_at": "2030-01-02T10:00:00Z",
  "end_at": "2030-01-02T18:00:00Z",
  "ttl_minutes": 15,
  "items": [
    {"product_id": 1, "quantity": 2},
    {"product_id": 2, "quantity": 1}
  ]
}
```

Пример PowerShell для локального демо с датами относительно текущего времени:

```powershell
$headers = @{ 'X-API-Key' = 'demo-operator'; 'Idempotency-Key' = [guid]::NewGuid().ToString() }
$start = [DateTime]::UtcNow.AddDays(1)
$body = @{
  label = 'Учебный концерт'
  start_at = $start.ToString('o')
  end_at = $start.AddHours(6).ToString('o')
  items = @(@{ product_id = 1; quantity = 1 })
  ttl_minutes = 15
} | ConvertTo-Json -Depth 4
Invoke-RestMethod 'http://127.0.0.1:8000/api/bookings' -Method Post -Headers $headers -Body $body -ContentType 'application/json; charset=utf-8'
```

Ответ `201` содержит UUID, человекочитаемый `reference`, период, статус `hold`, срок резерва, стабильный `created_by`, снимок имени `created_by_name`, итог в копейках и позиции с сохранёнными ставками.

Для безопасного сетевого повтора сохраните **тот же ключ и то же тело**. Нормализация допускает эквивалентный часовой пояс и другой порядок позиций. Повтор возвращает ту же бронь с текущим статусом. Изменённый запрос с тем же ключом получает `409`.

Перенос принимает только `start_at` и `end_at`. Остальные поля запрещены. Он не меняет состав и не продлевает TTL. Цена пересчитывается по сохранённым ставкам и новой длительности.

## Доступность

Каждая строка результата содержит:

- `available` — минимальный свободный остаток во всём запрошенном периоде;
- `peak_reserved` — пиковую занятость;
- `physical_available` — физически не выданное количество прямо сейчас;
- `overdue_quantity` — выданные единицы, срок возврата которых уже прошёл;
- `segments` — отрезки с `start_at`, `end_at`, `reserved`, `booking_ids`.

Чтение не удерживает ресурс. Конкурентная запись может изменить результат сразу после ответа. Окончательная проверка выполняется при резервировании и выдаче.

## Ошибки

```json
{
  "error": {
    "code": "capacity_conflict",
    "message": "Недостаточно оборудования на выбранный период",
    "details": {
      "conflicts": [
        {
          "product_id": 1,
          "name": "Колонка",
          "capacity": 3,
          "requested": 2,
          "reserved": 2,
          "start_at": "2030-01-02T10:00:00Z",
          "end_at": "2030-01-02T12:00:00Z",
          "booking_ids": ["uuid-занявшей-ресурс-брони"]
        }
      ]
    }
  }
}
```

`401 unauthorized` — неверный ключ; `403 forbidden` — недостаточно прав; `404 not_found` — объект отсутствует. Ошибки полей, даты, длительности, TTL и слишком большой суммы возвращают `422`. Конфликт ресурса, ключа или перехода — `409`.

Коды для логики клиента: `capacity_conflict`, `physical_stock_conflict`, `idempotency_conflict`, `invalid_transition`, `outside_window`, `invalid_input`, `invalid_interval`, `past_interval`, `quote_too_large`, `sku_conflict`.

## Альтернативные периоды

`POST /api/alternatives` принимает `start_at`, `end_at`, `search_until`, `items` и `limit` 1–5. Длительность сохраняется точно, весь вариант должен заканчиваться до горизонта, а горизонт ограничен 30 сутками от начала. Авторизация нужна, роль наблюдателя достаточна. Поиск ничего не резервирует.

Ответ: `duration_microseconds` (целое число), `generated_at`, `advisory`, список вариантов с `start_at`, `end_at`, включительным `latest_start`, предварительной стоимостью и минимальными доступными количествами. При отсутствии вариантов `reason` объясняет `no_window` или `insufficient_fleet`. Полный контракт и примеры границ — в [описании алгоритма](alternatives.md). Ошибка горизонта имеет код `invalid_horizon` и статус `422`.


## Числовые ID и ошибки хранилища

`product_id` и `before_id` — целые числа 1…2147483647, одинаково ограниченные в API и сервисе. Выход за границы возвращает `422`, допустимый отсутствующий объект — `404`. Текст не допускает NUL и одиночные суррогаты Unicode; кириллица и переводы строк разрешены.

При временной занятости ответ имеет HTTP `503`, код `storage_busy`, `details.retryable: true` и заголовок `Retry-After: 1`. Для взаимной блокировки используется `transaction_retry`, для распознанной потери соединения — `storage_unavailable`. Другие ошибки БД возвращают безопасный `500 storage_error` с `details.retryable: false`, без SQL и секретов. Уникальные бизнес-конфликты сохраняют свои прежние коды.

Ожидание блокировки задаётся `ORDERFLOW_LOCK_TIMEOUT_MS` (50–30000 мс, по умолчанию 2000), но не является общим пределом длительности HTTP. После неизвестного результата создания повторяйте прежний запрос с тем же `Idempotency-Key`: сервер не обещает откат при потере ответа после commit.
